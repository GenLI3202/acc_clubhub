## Track 1C — 首批真实内容

**原则：一篇真实内容 > 五篇 AI 占位符。**
**顺序：有素材的先做，不要等完美。**

```mermaid
flowchart LR

    E --> F
```

### 核心班子建议配置

| 角色 | 职责 | 建议人选 | 状态 |
|------|------|----------|------|
| 骑行活动组织 | 定期骑行安排 + 领骑 | 张怎样、ZDY | ⬜ 待确认 |
| 内容组织（骑行故事） | 媒体发文 + 征稿协调 | 小沈 | ✅ 已有 |
| 器械知识 | 维修 Workshop + 装备帖 | 林哥 | ⬜ 待确认 |
| 科学训练 | 训练内容 + 安全科普 | 马公梅、说话人B | ⬜ 待确认 |
| **影像记录** | **每次骑行拍照/视频** | **需转移出去** | ⬜ 必须换人 |
| **平台运营** | **小红书 + B站 发帖** | **需转移出去** | ⬜ 必须换人 |
| 网站运维 | 网站更新 + 技术问题 | 小沈 | ✅ 已有 |

> **聚餐的唯一成功标准**：影像记录和平台运营不再由小沈负责。否则只是换了个叫法，问题没变。

## 内容飞轮：一石多鸟

```mermaid
flowchart TD
    RIDE["🚴 一次骑行活动"] --> P1 & P2 & P3 & P4

    P1["📅 活动页\n（events/）\n提前发布，收集报名"]
    P2["📸 照片归档\n48小时内\n→ 共享文件夹"]
    P3["📝 骑行故事\n一周内\n→ media/ 发布"]
    P4["📱 社媒内容\n小红书 + B站\n图文或短视频"]

    P2 --> P3
    P2 --> P4

    P3 --> FLYWHEEL["🔄 内容飞轮\n每次活动都产出\n网站 + 社媒内容"]
    P4 --> FLYWHEEL
```

**飞轮转起来的前提**：每次重要骑行指定一名"影像官"，48小时内归档照片。没有这个 SOP，车影骑踪永远空着。
