# Issue #174：Android 补齐执行 Prompt

核对日期：2026-09-28。源码基线：`3eb11148`。
依据：https://github.com/GenLI3202/acc_clubhub/issues/174
读取时 issue 为 OPEN，无评论；本次未修改远端 issue。

本次仅检查仓库源码、现有记录并运行移动端测试与类型检查；
没有检查用户手机已安装 APK，也没有验证已部署 API 或操作生产数据。
不能将以下源码判断等同于手机版本或线上部署状态。

## 核对结果

- 已有：独立 Preact/Capacitor 工程、本地打包资源、中英德、公开活动内容、
  邮箱报名、名额/取消提示、官网按钮、Europe/Berlin 日期显示。
  入口包括 `mobile/capacitor.config.ts`、`mobile/src/app.tsx`、
  `mobile/src/components/ContentDetail.tsx`、`mobile/src/lib/content.ts`。
- 缺失：管理员登录/退出、活动及报名名单、签到、个人取消/恢复、活动改期/取消、
  通知操作的移动界面。`mobile/README.md` 明确排除后台及登录；
  `mobile/src/services/api.ts` 仅有公开状态、报名、订阅接口。
- 不完整：详情日期及报名时间判断仍使用 feed metadata，未合并实时日期和截止时间；
  `ContentDetail.tsx` 将 404 作为 `not_synced`，却仍可能开放报名；
  `idle` 状态也未被明确排除。实时请求依赖 slug/type/online，
  报名完成未通知父组件刷新名额。需按服务端契约修复，不能一律封禁首次报名。
- 不完整：`RegistrationForm.tsx` 缺少网站官方骑行的保险确认；
  仅禁用提交按钮，未在处理函数同步防重；异常统一显示错误，未识别结果未知；
  候补使用通用成功文案拼接后端 message，未独立展示候补位置。
- 契约缺口：`api.ts` 手写响应类型并强制断言，缺少与 OpenAPI 对齐的验证。
  `backend/routes/rsvp.py` 的公开报名会使用客户端 metadata 更新名额和截止时间，
  旧缓存可能覆盖数据库运营状态；需要与网站一起修复和验证。
- 内容验收缺口：feed 已在构建时调用 `resolveRecurringEvents`，不能称为没有周期支持；
  但仍需验证构建后跨周的场次更新、跨语言稳定 ID、回退、分页/边界及实时状态一致性。
- 范围差异：当前五入口为活动/媒体/器械/训练/关于，并包含日历等扩展。
  Issue 的三入口是建议方案；额外功能不是自动删除的依据，核心缺口是缺少管理能力。
- Android 试用验收未满足：现有脚本生成 debug 签名 APK，不能称为无签名；
  未见完整 pilot 发布签名、测试环境标识、密钥保管/升级方案和真机验收记录。
  `progress.md` 仍列有 feed 部署及真机测试待办；线上现状本次未复验。
- 本次验证：`mobile/` 下 `npm test` 为 7 个文件、34 项测试通过；
  `npx tsc --noEmit` 通过。现有测试不构成报名/管理端到端或真机验收。

范围与执行原则：

1. 基线与认证
核对本地和实际已部署的 API 能力，区分已实现、已部署、已测试。
只读核验生产公开接口；所有写入验证使用明确隔离的测试环境。
记录网站已有管理员身份验证、Cookie/JWT、CORS、单活跃会话政策。
在 Android 原生壳验证认证请求、退出、过期、撤销及网站/App 相互登录。

不将管理员秘密打包到客户端，也不使用远程网站外壳代替本地管理界面。

2. 活动契约与实时状态
以 FastAPI Pydantic/OpenAPI 为权威，生成或验证客户端契约。
复用现有 feed、服务及 shared 工具，保持事务在 API 层。
明确跨语言 event/occurrence 标识、缺失翻译回退、分页或有界读取、
发布可见性、内容刷新及 Europe/Berlin/DST 行为，隐藏未发布排班和私人数据。
周期 feed 已有构建期解析：重点修复跨周/暂停/取消/改期后的陈旧场次问题。
列表及详情合并服务端日期、截止时间、取消/改期、容量和名额；
报名成功、恢复前台及刷新后重新验证状态。
明确 404/未同步场次契约：未经确认不能开放写入，
同时保留合法已发布活动首次报名的受信任服务端同步路径。
修复公开报名用客户端旧 metadata 覆盖名额/截止时间等运营字段的问题；
不依赖客户端证明活动公开或规则有效。后端及网站调用同步更新，
并用相同 fixture 验证网站/App 对周期、取消、改期活动显示一致。

3. 骑友报名
对齐网站官方骑行的隐私/保险说明、链接和必需确认，提供三语文案。

业务拒绝和结果未知状态。请求有合理超时，不能因超时虚报失败或成功，
不能盲目重试会写数据库或发邮件的请求。
若引入幂等/结果查询，以服务端契约实现；查询个人报名只能使用有效
所有权 token/验证流程，禁止仅凭邮箱查询，也不扩展成账号历史系统。
服务端验证截止、取消、可见性、容量及并发报名；成功后刷新实时名额。
验证空态、加载、离线、软键盘、安全区、返回键及官网往返。

4. 管理员移动界面
实现有效登录/退出、分页活动及报名名单、签到/撤销签到、个人取消/恢复、
活动改期/取消及现有通知操作；复用后端权限和候补递补规则。
每个请求校验权限；退出/过期/撤销后清除私人状态，并阻止迟到响应恢复数据。
有影响操作必须展示对象、变更和发送范围并确认。
分别展示数据库操作结果和邮件 sent/skipped/failed，不能把邮件失败显示成
数据回滚，也不能为重发邮件盲目重复数据变更。
